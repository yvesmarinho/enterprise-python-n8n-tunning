# CHAT-20260508-122500 — F16 Revisado: RabbitMQ Exporter (Opção A)

**Data**: 2026-05-08
**Sessão**: 2026-05-08
**Contexto**: F16 original (Bull queue metrics) está obsoleto porque wf001/wfdb01 usa N8N_QUEUE_MODE=rabbitmq. Usuário solicitou implementar Opção A (rabbitmq_exporter) em wfdb01 para homologação.

---

## Resumo

Implementação completa da Opção A para substituir o F16 original:
- Novo role Ansible `rabbitmq_exporter` com deploy via `docker-compose.override.yml`
- Playbook `f16-rabbitmq-exporter.yml` com SPA knock + deploy + rollback
- Atualização de `prometheus.yaml` via `blockinfile` (SIGHUP reload, sem restart)
- Método de coleta de arquivos remotos corrigido: `ansible slurp` + `read_file` (não `cat` via terminal)
- Correção do `ansible.cfg`: chave SSH adicionada em `ssh_args`; corrigido carregamento do cfg via `ANSIBLE_CONFIG=`

---

## Decisões Tomadas

1. **RabbitMQ exporter no stack rabbitmq** (não no observability): mantém responsabilidade isolada, exporter tem acesso direto ao container `rabbitmq` via `app-network`
2. **`docker-compose.override.yml`** no `/opt/docker_user/rabbitmq/`: padrão já estabelecido no projeto (igual ao F16 original para n8n)
3. **`blockinfile`** com marker para prometheus.yaml: idempotente e reversível via `state: absent` no rollback
4. **SIGHUP** para reload do Prometheus: sem restart, zero downtime
5. **Credenciais via `-e` ou vault**: `rabbitmq_exporter_password` não commitada, precisa ser fornecida em runtime
