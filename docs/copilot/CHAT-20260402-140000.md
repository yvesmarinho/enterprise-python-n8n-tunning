# CHAT-20260402-140000 — PT001 + PT002: Validação wfdb01 + Pesquisa docs N8N + Correções B1–B5

## Resumo

Execução das pré-tasks PT001 e PT002 da feature `001-001-tunning-instrumentacao`. PT001
validou que `N8N_METRICS_INCLUDE_QUEUE_METRICS=true` está funcionando corretamente em
wfdb01 com N8N 2.13.2. PT002 mapeou todas as variáveis de monitoramento disponíveis
na documentação oficial. A descoberta revelou 5 bugs (B1–B5) nos artefatos gerados nas
sessões anteriores, todos corrigidos nesta sessão.

---

## Decisões Tomadas

1. **Metrics URL vs porta**: wfdb01 expõe métricas exclusivamente via HTTPS/Traefik em
   `https://testn8n.vya.digital/metrics` — não há mapeamento de porta direta ao host.
   Decisão: `check_n8n_metrics.py` passa a usar `--metrics-url URL` em vez de `--host/--port`.

2. **Nomes de métricas N8N 2.x**: As métricas de fila no N8N 2.x usam o prefixo
   `n8n_scaling_mode_queue_jobs_*`, não `n8n_queue_*` como estava documentado.

3. **Arquivo compose**: O arquivo em wfdb01 é `docker-compose.yaml` (com `.yaml`),
   não `docker-compose.yml`.

4. **wait_for → uri**: O task de aguardo pós-deploy em f16_queue_metrics.yml foi convertido
   de `wait_for` (TCP port check) para `uri` (HTTP check) para refletir a arquitetura
   real via Traefik HTTPS.

## Variáveis de Monitoramento Adicionais Identificadas (PT002)

### Recomendadas para habilitar no wfdb01 (e futuramente wf001):

| Variável | Default | Utilidade |
|----------|---------|-----------|
| `N8N_METRICS_INCLUDE_WORKFLOW_ID_LABEL` | false | **ALTA** — label workflow ID nas métricas de execução |
| `N8N_METRICS_INCLUDE_NODE_TYPE_LABEL` | false | **ALTA** — profiling por tipo de nó |
| `N8N_METRICS_INCLUDE_CACHE_METRICS` | false | **MÉDIA** — cache hits/misses |
| `N8N_METRICS_QUEUE_METRICS_INTERVAL` | 20s | configurável se precisar de resolução maior |

### Vars de log relevantes:
- `N8N_LOG_FORMAT=json` — útil para produção/observabilidade
- `DB_LOGGING_ENABLED=true` + `DB_LOGGING_MAX_EXECUTION_TIME=500` — queries lentas
